# 데브로그 글 첨삭

대상은 사용자가 지정한 글입니다. 지정하지 않았으면 IDE에 열린 `src/content/devlog/` 파일을 쓰고, 그것도 없으면 어떤 글인지 물어봅니다. 글 하나를 처음부터 끝까지 읽은 뒤 아래 순서대로 작업합니다.

## 공통 원칙

- 글쓴이의 사실, 주장, 경험, 말투를 지킵니다. 글에 없는 사실, 수치, 일화를 지어내지 않습니다.
- 글의 구조와 섹션 순서는 필요할 때만 바꿉니다.
- 다음은 고치지 않습니다: 코드 블록과 인라인 코드 안의 내용, URL, `import` 줄, 컴포넌트 이름과 prop 이름, `pubDate`, `updatedDate`, `tags`, 고유명사와 디자인 토큰 이름(Night Desk, Lamp Gold 등).
- 파일 이름은 바꾸지 않습니다. 슬러그가 URL이 되므로, 슬러그에 오타가 있으면 고치지 말고 알려 줍니다.

## 1. PROMPT 지시문 처리

`PROMPT(...)`는 글쓴이가 AI에게 남긴 지시문입니다. 괄호 안 문장을 그대로 싣지 않고, 지시를 수행한 결과로 `PROMPT(...)` 전체를 바꿉니다. 본문과 frontmatter(`title`, `description`)를 모두 찾습니다. 코드 블록과 인라인 코드 안의 `PROMPT(...)`는 예시이므로 건드리지 않습니다.

- 괄호 안에 괄호가 있으면 짝이 맞는 닫는 괄호까지가 지시문입니다.
- 지시문이 짧거나 문장이 끝나지 않았으면 놓인 자리로 뜻을 판단합니다. 예를 들어 `description: 'PROMPT(글 내용을 보고 )'`는 글 내용을 보고 설명을 쓰라는 뜻입니다.
- 결과는 글의 문맥에 이어지게 쓰고, 이 스킬의 문체 규칙을 따릅니다. `description`은 글 목록과 검색 결과에 보이는 한두 문장으로 씁니다.
- 수행하려면 글에 없는 사실이 필요하면 지어내지 말고 `PROMPT(...)`를 그대로 둔 뒤 무엇이 필요한지 알려 줍니다.

## 2. 첨삭

- 맞춤법, 띄어쓰기, 오타를 고칩니다.
- 어색한 표현, 번역투, 끊기거나 비문인 문장을 자연스럽게 고칩니다.
- 같은 단어나 표현의 반복을 줄이고, 뜻이 겹치는 문장은 하나로 합칩니다. 강조나 리듬을 위해 일부러 반복한 표현은 둡니다.

## 3. 해요체로 통일

본문 문장, Callout 안의 문장, 문장으로 끝나는 `title`, `description`, 제목을 해요체(`-해요`, `-이에요`, `-예요`, `-어요`)로 맞춥니다. `-습니다`, `-한다`, `-함`이 섞이지 않게 합니다.

- 같은 어미가 연달아 나오면 문장을 합치거나 어순을 바꿔 단조롭지 않게 합니다.
- 말끝을 지나치게 귀엽게 만들지 않고, 글쓴이의 차분한 말투를 유지합니다.
- 다음은 그대로 둡니다: 명사로 끝나는 제목과 목록 항목(`앞으로 쓸 이야기`), 인용문, AI에게 전달한 프롬프트 원문, 코드.

## 4. GitHub 저장소 상자

`https://github.com/소유자/저장소` 형태의 저장소 URL은 일반 링크 대신 `RepoCard`로 보여 줍니다. 코드 블록 안의 URL과 이미 `RepoCard`인 것은 제외합니다.

```mdx
import RepoCard from '../../components/RepoCard.astro';

<RepoCard url="https://github.com/jusiai-games/예시-저장소" description="저장소를 한 줄로 설명하는 문장이에요." />
```

- URL이나 링크만 있는 문단, 목록 항목은 `RepoCard`로 바꿉니다.
- 문장 안의 URL은 문장을 자연스럽게 고쳐 URL을 빼고, 그 문단 바로 아래에 `RepoCard`를 둡니다. 저장소 하나가 글에 여러 번 나오면 카드는 처음 한 번만 두고, 이후에는 저장소 이름만 씁니다.
- `description`은 글에 나온 내용으로 쓰고, 근거가 없으면 생략합니다. 저장소 내용을 추측하지 않습니다.
- `import`는 frontmatter 아래 다른 `import`와 함께 두고, 쓰이지 않게 된 `import`는 지웁니다.
- 프로필(`github.com/jusiai-games`), 파일, 이슈, PR 링크는 `RepoCard`가 받지 않으므로 일반 링크로 둡니다. URL 끝의 `/`와 `.git`은 있어도 됩니다.

## 5. 확인과 보고

1. 글에 처리하지 않은 `PROMPT(`가 남았는지, `-습니다`, `-습니까`가 남았는지 검색합니다.
2. `npm run build`를 실행해 오류와 경고가 없는지 확인합니다.
3. 커밋하지 않고, 다음을 짧게 알려 줍니다.
   - 바뀐 내용 요약과 `PROMPT`를 바꾼 결과
   - 뜻이 바뀌었을 수 있어 글쓴이가 확인할 문장
   - 고치지 않은 문제: 슬러그 오타, 사실이 의심스러운 내용, 파일 이름 날짜와 `pubDate`가 다른 경우, 남겨 둔 `PROMPT`
